01 / The data

Real conveyor images.
Explicit labels.

The model learns from the SteelDS a3 dataset, a published collection of steel scrap with visible copper on a conveyor. We retained its official training and validation partitions: five training recordings and one validation recording. In this project, validation is called development because it guides checkpoint and operating-point selection.

That is 287,454 object annotations across 8,203 images. An annotation is a labeled object appearance in a frame; the same physical piece can appear in many frames. The labels describe steel and visible copper, giving the model a concrete visual task.

Split integrity and label handling

Official recording membership was preserved, with no random reshuffling or class balancing. Thirty-four publisher training frames and six validation frames without label files were excluded, leaving 6,681 training and 1,522 development frames; they were never treated as an empty belt.

EXP009 acquired and used TRAIN and VAL only. TEST was excluded from training and selection. Earlier project work had already exposed some SteelDS test imagery, so the website identifies historical exposure separately when presenting video results. The next independent evaluation requires new recordings and a split at the physical-piece or campaign level.

Dataset: SteelDS a3 · CC BY 4.0. Publisher credits appear in sources.

02 / Preparation

Keep the detail.
Vary the view.

Source images became RGB JPEG derivatives with the original aspect ratio and a maximum dimension of 1,280 pixels, saved at JPEG quality 90. Positive-area annotation polygons were converted to their enclosing boxes, retaining tiny and boundary objects. Image and label fingerprints tied the training inputs to a saved manifest.

  1. 01 · Preserve the splitKeep each frame in its publisher recording and partition.
  2. 02 · Transform togetherResize images and boxes consistently; retain valid labeled objects.
  3. 03 · Train at 640Resize and pad model inputs for the selected 640-pixel configuration.

During training, controlled augmentation exposed the model to changes in position, size and brightness. Hue jitter was set to zero to preserve the material-color cue. Geometric changes transformed the boxes with the images.

Saved augmentation settings
  • Geometry: rotation ±10°, translation parameter 0.1, scale parameter 0.5, horizontal flip probability 0.5; vertical flipping disabled.
  • Color: HSV hue 0.0, saturation 0.25, value 0.35.
  • Composition: mosaic probability 0.4, disabled for the final 10 epochs; mixup and cutmix disabled.

These are saved training parameters. Inference uses a single image with augmentation disabled.

03 / Fine-tuning

A pretrained base.
A focused model.

We initialized the Ferrosift model from the published Ultralytics YOLO26s pretrained checkpoint and fine-tuned it on the two SteelDS classes. The reference was separately fine-tuned from YOLO11s pretrained weights using the same development data and planned settings. Both output heads were adapted from 80 pretrained classes to the two project classes. Ferrosift’s contribution here is the trained configuration, data preparation, operating-point selection and evaluation workflow.

The 960-pixel arm reached the highest native metric and stopped after 12 epochs without improvement. It is not the checkpoint used in the website comparison. Among the two 640-pixel models, the reference led on this broad checkpoint metric. Ferrosift led on the later task-specific result: copper recall at the strict alarm budget. Both measurements matter because finding more copper at a chosen operating point is different from maximizing average detection quality across classes and thresholds.

The comparator is a reproducible reference model evaluated on the same images. Because the model families differ, this experiment combines architecture and fine-tuning choices. A matched YOLO26s baseline and ablations are planned to isolate which choices contribute most.

Separate follow-on training: EXP010

A later paired experiment initialized both arms from the EXP009 YOLO11s checkpoint and completed 12 fixed epochs per arm. Its saved completion record contains no validation or test metrics. That work remains a separate research branch; the website continues to use the identified EXP009 checkpoints.

The exact upstream pretraining corpus and physical-object overlap have not been independently audited; checkpoint URLs and hashes identify the initialization used.

05 / Evaluation

More copper found.
Alarms accounted for.

Using the saved development predictions, we selected a copper-confidence threshold for each checkpoint. The objective was to maximize copper annotation recall while keeping (steel matches + unmatched copper alarms) ÷ steel annotations at or below 1%.

On our labeled conveyor evaluation, Ferrosift detected 94.0% of copper annotations versus 85.6% for the YOLO11s reference, an 8.4 percentage-point improvement.

Historical matching and threshold selection

The historical routing diagnostic processes copper predictions by descending confidence, then box coordinates and original prediction order. Each prediction is assigned to the highest-overlap still-unmatched annotation at intersection-over-union (IoU) ≥0.5. Ground-truth class is inspected after assignment. This is class-blind greedy matching; steel predictions do not consume assignments that could hide a copper alarm.

Threshold selection considers the saved confidence values, includes scores equal to the threshold, and counts misses in the full copper denominator. The model and thresholds were selected using these development frames. The ≤1% measure is an annotation-level alarm burden, distinct from conventional false-positive rate and physical steel loss.

How to read a selected-video score

The video lab generates a new comparison from the frozen checkpoints on identical decoded frames from each viewing copy. A clip receives measured scores only where label-to-frame alignment has been verified. Unlabeled frames are never assumed to contain no objects.

For these new clip scores, geometry-only one-to-one assignment maximizes the number of matches at IoU ≥0.5 and then total IoU. This differs from the historical greedy routing diagnostic above. Viewing-copy encoding, frame coverage and the recorded runtime also differ, so the clip score stands on its own rather than inheriting the 1,522-frame aggregate.

A video without verified labels is marked “Accuracy unavailable: no verified labels.” The playable footage and saved detections remain available for inspection.

06 / Inference

From a frame
to a decision.

At inference time, the trained weights transform an image into boxes, class labels and confidence scores. The selected configuration resizes and pads to a square 640-pixel input, runs one image at a time, and applies the same class-aware non-maximum suppression settings to both models. Copper detections become alarms only when their score reaches the model’s frozen threshold.

  1. 01 · Read one frameDecode the same image pixels for both checkpoints.
  2. 02 · Predict and filterCompute boxes and scores, apply common NMS, then the frozen copper threshold.
  3. 03 · Inspect and measureSave predictions and compare with verified annotations where available.

The website serves precomputed model outputs. Selecting a clip loads its saved results alongside the source video. The comparison panels show sampled stills with their own timestamps; video playback speed is separate from inference speed.

Frozen inference settings and runtime separation

Selected settings: 640-pixel square preprocessing (rect=false), FP32, CPU, batch 1, confidence floor 0.001, NMS IoU 0.7, maximum 1,000 retained detections, class-aware NMS, and inference augmentation disabled. The packaged backend is checked as end2end=false. Class 0 is steel; class 1 is visible copper.

The historical CPU evaluation used PyTorch 2.8.0+cpu and Ultralytics 8.4.175. The current video release records its actual local runtime in the clip provenance. Training, historical evaluation, fresh video inference and browser playback are separate stages; their runtime measurements are not interchangeable.

Visible-material detection is the current model task. Tracking, sensor fusion, ejection timing, physical recovery and purity are the next engineering measurements. Fresh campaigns across lighting, loading, camera views and materials will test how far the model generalizes.
